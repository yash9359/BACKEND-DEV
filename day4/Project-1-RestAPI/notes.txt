📘 Express CRUD (JSON + fs) — Proper Notes
1️⃣ Project ka Goal

Express server banana

Users ka data MOCK_DATA.json se read karna

GET / POST / PATCH / DELETE APIs banana

Naya user add karna + file me save karna

2️⃣ Required Modules
const express = require("express");
const users = require("./MOCK_DATA.json");
const fs = require("fs");

Explanation:

express → server + routing

users → JSON file ka data (RAM me load hota hai)

fs → file ko permanently update karne ke liye

⚠️ Ye line unnecessary hai (VS Code auto-import):

const { json } = require("stream/consumers"); // ❌ remove

3️⃣ App & Port Setup
const app = express();
const PORT = 8000;


app → Express application

PORT → server kis port pe chalega

4️⃣ Middleware (Body Parsing)
app.use(express.urlencoded({ extended: false }));

Kaam:

Form data (x-www-form-urlencoded) ko

req.body me convert karta hai

📌 Agar JSON body chahiye ho:

app.use(express.json());

5️⃣ /users Route (HTML Response)
app.get('/users', (req, res) => {
    const html = `
    <ul>
    ${users.map((user) => `<li>${user.first_name}</li>`).join("")}
    </ul>
    `;
    res.send(html);
});

Ye route kya karta hai?

Browser ke liye HTML response

Users ke first name list me dikhata hai

📌 Use case:

Browser view

Simple frontend testing

6️⃣ /api/users (GET – All Users)
app.get("/api/users", (req, res) => { 
    return res.json(users);
});

Explanation:

Pure users ka data JSON format me deta hai

Mostly frontend / mobile apps ke liye

7️⃣ POST /api/users (Create User)
app.post("/api/users",(req,res)=>{
    const body = req.body;

    users.push({ ...body, id: users.length + 1 });

    fs.writeFile(
        "./MOCK_DATA.json",
        JSON.stringify(users),
        (err) => {
            return res.json({ status: "success", id: users.length });
        }
    );
});

Step-by-step flow:

req.body se naya user data aata hai

{ ...body } → deep copy (reference issue se bachne ke liye)

users.push() → RAM me add

fs.writeFile() → file me permanently save

📌 push kyun?

Purane users delete hone se bachane ke liye

📌 fs kyun?

Server restart ke baad bhi data rahe

8️⃣ /api/users/:id (Dynamic Route)
app.route("/api/users/:id")


:id → URL se dynamic value

Example:

/api/users/5

8.1️⃣ GET User by ID
.get((req,res)=>{
    const id = Number(req.params.id);
    const finduser = users.find((u)=> u.id === id);
    return res.json(finduser);
})


req.params.id → string hota hai

Number() → comparison ke liye number banaya

find() → matching user nikala

8.2️⃣ PATCH User (Placeholder)
.patch((req,res)=>{
    return res.json({status:"pending"});
})


Future me user update logic yahan aayega

8.3️⃣ DELETE User (Placeholder)
.delete((req,res)=>{
    return res.json({status:"pending"});
})


Future me user delete logic yahan aayega

9️⃣ app.route() use kyun kiya?
app.route("/api/users/:id")

Fayde:

Same URL ke sab methods ek jagah

Code clean + readable

Route change karna easy

1️⃣0️⃣ Server Start
app.listen(PORT, () => {
    console.log(`Server Started at PORT: ${PORT}`);
});

Important note:

Server start hone se koi request automatic nahi jaati

Browser tab GET bhejta hai jab URL open hota hai

🧠 Important Concepts Recap
✔️ Browser

Address bar → sirf GET

POST / PATCH → Postman / fetch / form

✔️ push()

RAM me data add karta hai

Purana data safe rakhta hai

✔️ fs.writeFile()

Poora JSON overwrite karta hai

Isliye pehle push zaroori

✔️ { ...body }

Deep copy

Side-effects se protection
