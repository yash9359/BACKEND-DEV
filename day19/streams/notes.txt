🔥 Stream kya hota hai?

Stream = data ka flow, jo thoda-thoda (chunks) me aata–jata hai.
Poora data ek saath load nahi hota.

📌 Socho paani ki pipe:

readFile → poora tank ek baar me utha ke laana ❌

stream → pipe se paani dheere-dheere aata ✔️

❓ Stream kyu use hota hai?

Main reasons 👇

1️⃣ Memory bachane ke liye

Agar file 100MB / 1GB ki hai:

fs.readFile() → poori file RAM me ❌ (danger 💥)

createReadStream() → chunk by chunk ✔️

👉 RAM overload nahi hoti

2️⃣ Fast response

Client ko pehla chunk turant mil jata hai
Wait nahi karna padta poori file load hone ka

Netflix example 🎥
➡️ Movie download hone se pehle hi chal jaati hai
➡️ Ye hi streaming

3️⃣ Large data ke liye best

Video

Audio

Logs

Big text files

HTTP responses

🧠 Tumhare code me kya ho raha hai?
const stream = fs.createReadStream("./sample.txt","utf-8");


➡️ File ko chunks me read kar raha hai

stream.on("data",(chunk)=>{
    res.write(chunk);
});


➡️ Jaise hi chunk aaya → client ko bhej diya

stream.on("end", ()=>{
    res.end();
})


➡️ File khatam → response close

⚡ Client ko data live milta rehta hai

🤔 Agar stream na use karo to?
fs.readFile("./sample.txt",(err,data)=>{
    res.send(data);
});


❌ Pehle poori file RAM me
❌ Phir client ko bhejo
❌ Large file = server slow / crash

🧪 BONUS: Stream ek line me (best practice)
fs.createReadStream("./sample.txt").pipe(res);


🔥 Ye internally wahi data + end sambhal leta hai

🧠 Ek line intuition (exam ke liye):

Stream data ko poora load karne ke bajay chhote-chhote parts me process karta hai, jisse memory efficient aur fast response milta hai.

File ka chhota tukda (≈ 64KB)

64KB | 64KB | 64KB | ...

3️⃣ Stream ke types (IMPORTANT)
🔹 1. Readable Stream
➡️ Data padhta hai

fs.createReadStream("file.txt");
Examples:

File read

Request (req)

Video stream

🔹 2. Writable Stream
⬅️ Data likhta hai

fs.createWriteStream("out.txt");
Examples:

File write

Response (res)

🔹 3. Transform Stream ⭐
➡️⬅️ Read bhi + modify bhi + write bhi

zlib.createGzip()
Examples:

Zip

Encryption

JSON → CSV

4️⃣ Pipe kya hai? (HOW)
pipe = ek stream ka output, dusri stream ka input

🧠 Formula:

source.pipe(destination)

fs.createReadStream("sample.txt")     // Readable
  .pipe(zlib.createGzip())            // Transform
  .pipe(fs.createWriteStream("sample.zip")); // Writable
Step-by-step:
ReadStream chunk deta hai

Gzip us chunk ko compress karta hai

WriteStream compressed chunk disk pe likhta hai

📌 Ek bhi moment pe poori file memory me nahi hoti

5️⃣ zlib kya hai? (ZIP ka boss)
zlib Node ka compression library hai
internally C language me likha hua (fast 🔥)

createGzip() kya karta hai?
Input stream leta hai

Output me compressed stream deta hai

🧠 Ye ek Transform Stream hai

7️⃣ Stream vs Normal File Read (Interview ready)
Point	readFile	Stream
Memory	High	Low

Production	❌	✅
8️⃣ Express me stream ka real use
File download (best way)
app.get("/download", (req, res) => {
  res.setHeader("Content-Disposition", "attachment; filename=sample.txt");

  fs.createReadStream("sample.txt").pipe(res);
});
Zip banake direct user ko bhejna 🔥
app.get("/zip", (req, res) => {
  res.setHeader("Content-Encoding", "gzip");

  fs.createReadStream("sample.txt")
    .pipe(zlib.createGzip())
    .pipe(res);
});
💥 Disk pe zip bhi nahi bani, direct user ko

9️⃣ Backpressure (Advanced but zaroori)
Agar:

Read fast

Write slow

Node automatically bolega:

ruk ja bhai, pehle likhne de

Pipe backpressure handle karta hai
manual on("data") me nahi hota

Streams = large data ko safely, efficiently, aur fast handle karne ka tareeka
